### 已对接接口的页面字段缺口

许可证列表页 4 列无数据来源（新后端许可证模型无以下字段）：

- `securityLevel`（风险等级）—— 页面该列空白
- `gplCompatible`（GPL 兼容）—— 页面显示"不兼容"（误导性默认态）
- `isOsi` / `isFsf`（OSI/FSF 认证）—— 页面显示 × 图标

**处理建议**：① 后端在许可证模型补充字段；② 或前端改版移除这 4 列。

## 三、缺口 A：任务数据依赖（11 条）

前端有对应页面，但所有数据按 task 组织，`/work/tasks` 当前为空，接通也只能返回空。

| 接口 | 对应前端页面 |
|---|---|
| GET /work/task | 任务（项目）详情 |
| GET /work/sbom | SBOM 风险扫描 |
| GET /work/sbom-inputs | SBOM 输入清单 |
| GET /work/report、/work/report.html | 报告管理 |
| GET /work/ai-drafts | AI 草稿列表 |
| POST /work/score | 评分 |
| POST /work/compare | 任务对比 |
| POST /work/cluster | 文本聚类 |
| POST /work/enrich | 漏洞补充查询 |
| POST /work/dependency-range | 依赖版本范围 |

**参数说明**：任务维度接口统一用 `?id=<任务id>`（yaml 锚点 &id003，"对象或任务ID"）。

## 四、缺口 B：写/流程操作（7 条）

不能通过适配层"假接"（会产生伪造状态），须按真实业务流程对接：

`POST /work/import`（数据导入）、`POST /work/transition`（任务流转）、`POST /work/annotation`（证据注释）、`POST /work/review`（评审，当前 403）、`POST /work/rollback`（回滚）、`POST /work/governance`（治理创建）、`POST /work/governance/close`（治理关闭，403）

## 五、缺口 C：工具类接口（14 条）

接口实测活着（400 参数校验，认证通过），但 ① openapi.yaml **未定义 requestBody**（试探字段名均被 400 拒）；② 前端无现成承接页面。

- 许可证工具：`POST /expression`（已知字段 `value`）、`/normalize`、`/match`、`/extract`、`/compatibility`、`/candidates`、`/clauses`
- 特征/源码工具：`POST /work/feature-search`、`/work/feature-quality`、`/work/feature-provenance`、`/work/feature-compare`、`/work/source-compare`、`/work/license-classification`
- AI：`POST /work/ai-draft`

**潜在承接页面**：`src/views/home/log/sourceFeature.vue`（源码检测工具台，当前为静态演示页）可承接 feature 系列 5 条。

## 六、缺口 D：语义不匹配 / 权限不足（10 条）

| 接口 | 原因 |
|---|---|
| GET /health | 基础设施，不需要页面（可用于"关于系统"展示后端状态） |
| GET /audit | 许可证库统计计数，非操作日志列表（日志审计页语义不符） |
| GET /rules | 规则引擎版本信息，非组件规则 CRUD |
| GET /work/object | purl 精确单查，搜索页是关键词列表搜索，形态不符 |
| GET /work/repository | 单次仓库社区数据查询，社区健康页是评估记录结构 |
| GET /work/revisions、/work/revision | 有真实数据（评分模型修订），前端无对应页面 |
| GET /work/events | **403**：token 为 analyst 角色，审计日志需更高权限 |
| POST /work/review、/work/governance/close | **403**：需 reviewer/admin 角色 token |
